# Рабочие каталоги Git в DSH Desktop

Эта сборка предназначена для DSH `0.2.0-rc.2`. Она добавляет создание worktree из пустого чата Git-проекта и страницу «Рабочие каталоги Git» в настройках. На ней можно посмотреть ветки и изменения и открыть чат существующего worktree.

## Создание через Windows helper

Для режима, использующего `codex-worktree-start.ps1`, укажи в настройках плагина абсолютные пути:

```yaml
- id: dsh-simple-worktree
  config:
    windowsHelper: C:/Users/your-name/.codex/maintenance/codex-worktree-start.ps1
    worktreeRoot: C:/Users/your-name/.codex-worktrees
```

В новом чате Git-проекта нажми «Создать worktree», введи короткое имя латиницей и выбери «Создать и открыть». Например, для проекта `app` и имени `fix-login` будет показана ветка `codex/fix-login` и каталог `.codex-worktrees/app-fix-login`. DSH добавит созданный каталог как отдельный проект и откроет в нём чат. Рабочие файлы исходного каталога не изменяются.

По умолчанию выбирается основная ветка. Helper получает выбранную базу и использует соответствующую ветку `origin`, если она есть. Для новой задачи основной каталог должен быть чистым. Существующий worktree той же ветки открывается повторно без пересоздания. Имя приводится к строчным буквам, цифрам и дефисам и ограничивается 48 символами.

В этой сборке удаление и очистка записей через плагин отключены. Завершение каталога требует отдельной проверки его данных и Git-состояния. Ошибка добавления проекта в DSH сохраняет созданный worktree; кнопка «Добавить в DSH и открыть» повторяет регистрацию.

## Просмотр Git-изменений

Открой «Настройки → Рабочие каталоги Git», выбери конкретный проект и нажми кнопку «Изменения Git» рядом с проектом или рабочим каталогом. Выбери «Рабочие файлы», «Подготовлено к коммиту» или «Изменения ветки», затем файл из списка. Последний режим сравнивает закоммиченные изменения текущей ветки с общей точкой истории выбранной основной ветки. Пустое поле основной ветки использует ветку проекта по умолчанию.

Просмотр не изменяет файлы, индекс или ветки и не запускает внешние Git diff/textconv-программы. Новые неотслеживаемые файлы появятся после `git add`. Переименование показано как удаление старого файла и добавление нового. Для двоичных файлов отображается факт различия; для файлов с данными доступа — только путь. Слишком большие сравнения отклоняются целиком: предел составляет 500 файлов и 256 КиБ текста за один запрос.

## Установка пакета

Сначала проверь пакет в отдельном профиле Desktop. Для установки в основной профиль приложение должно быть полностью закрыто. Добавь проверенный пакет через штатный установщик DSH, задай пути helper и рабочих каталогов, затем открой приложение. Модель, подписка ChatGPT и история чатов не требуют замены.

## Проверки

В исходниках доступны сборка, проверка типов и тесты: `pnpm build`, `pnpm typecheck`, `pnpm test:unit`. Windows-тест отдельно проверяет передачу путей с апострофами и PowerShell-выражениями как обычных строк. Проверка настоящего Desktop и установленного helper проводится на тестовом Git-репозитории; результат не означает разрешения менять рабочие проекты.
