# Проверка переноса чата

Дополнение работает с Desktop 0.2.0-rc.2. Нативные исходники закреплены в
`native/source.json`; каждый включённый файл проверяется по SHA256.
`pnpm test` проверяет клиент, типы, обычную сборку и состав npm-пакета;
`pnpm check:relocation-sdk` дополнительно проверяет канонические Client-модули,
новые Remote-дескрипторы и отсутствие вложенных копий SDK. CI выполняет эти
проверки на Windows и Linux.

Полную проверку установленного Desktop выполняет
`node scripts/verify-native-session-relocation.mjs` с параметрами:

- `--resources`: каталог resources установленного Desktop;
- `--executable`: исполняемый файл этого Desktop;
- `--package`: точный собранный tgz дополнения;
- `--playwright`: абсолютный путь к установленному `playwright/index.mjs`;
- `--browser`: необязательный путь к отдельному Chromium/Chrome;
- `--output`: новый каталог отчёта. Существующий каталог отклоняется.

Сценарий создаёт собственный DSH_HOME внутри output, устанавливает пакет
штатным CLI и запускает настоящий установленный Desktop Host. Он проверяет
общий SDK и пять Client-компонентов, отказ занятого терминала, перенос через
Gateway, затем настоящий аутентифицированный UI: отмену, сохранение черновика,
A → B, полный перезапуск Host/браузера и возврат B → A. После удаления
дополнения прежний установленный reader должен прочитать тот же ID и исходный
префикс истории. Пакет возвращается в тестовый профиль штатным установщиком.

Модель объявляется локальным тестовым адаптером, который запрещает любые
запросы. Используются только искусственные чаты и проекты. Токен свежего Host
передаётся браузеру через IPC и не сохраняется в отчётах. Учетные файлы и
существующие пользовательские профили не читаются и не изменяются.

Результат — `verification.json`, отдельные отчёты фаз, aria-снимки и PNG.
Отчёт относится только к пакету с указанным SHA256. Локальные снимки содержат
пути искусственных проектов; их не нужно публиковать вместе с исходниками.

Нативные Windows/Linux проверки хранения, контекста, независимого писателя,
аварий и SDK находятся в парном PR DeepSeek Harness. Они дополняют этот UI
сценарий. Возврат пакета разрешён после возврата перенесённых чатов к исходным
каталогам; одной замены manifest для отката недостаточно.
