# Проверка переноса чата

Дополнение работает с Desktop 0.2.0-rc.2. Нативные исходники закреплены в
`native/source.json`; каждый включённый файл проверяется по SHA256.
`pnpm test` проверяет клиент, типы, обычную сборку и состав npm-пакета;
`pnpm check:relocation-sdk` дополнительно проверяет канонические Client-модули,
новые Remote-дескрипторы и отсутствие вложенных копий SDK. CI выполняет эти
проверки на Windows и Linux.

Полную проверку установленного Desktop выполняет
`node scripts/verify-native-session-relocation.mjs` с параметрами:

- `--resources`: каталог resources установленного Desktop;
- `--executable`: исполняемый файл этого Desktop;
- `--package`: точный собранный tgz дополнения;
- `--playwright`: абсолютный путь к установленному `playwright/index.mjs`;
- `--browser`: необязательный путь к отдельному Chromium/Chrome;
- `--output`: новый каталог отчёта. Существующий каталог отклоняется.

Сценарий создаёт собственный DSH_HOME внутри output, устанавливает пакет
штатным CLI и запускает настоящий установленный Desktop Host. Он проверяет
штатный глобальный Schedule, сохранение записи, созданной прежним владельцем,
нестандартные параметры хранения расписаний и их чтение прежней сборкой после
отката. Отдельный прогон установленных parser/composition API проверяет
missing/disabled, raw disabled-выражения, выключенного родителя, foreign/duplicate,
isolate/intercept, устаревший fingerprint и восстановление исходной конфигурации.
Далее проверяются
общий SDK и пять Client-компонентов, отказ занятого терминала, перенос через
Gateway, затем настоящий аутентифицированный UI: отмену, сохранение черновика,
A → B, полный перезапуск Host/браузера и возврат B → A. После удаления
дополнения прежний установленный reader должен прочитать тот же ID и исходный
префикс истории. Пакет возвращается в тестовый профиль штатным установщиком.

Модель объявляется локальным тестовым адаптером, который запрещает любые
запросы. Используются только искусственные чаты и проекты. Токен свежего Host
передаётся браузеру через IPC и не сохраняется в отчётах. Учетные файлы и
существующие пользовательские профили не читаются и не изменяются.

Результат — `verification.json`, отдельные отчёты фаз, aria-снимки и PNG.
Отчёт относится только к пакету с указанным SHA256. Локальные снимки содержат
пути искусственных проектов; их не нужно публиковать вместе с исходниками.

Нативные Windows/Linux проверки хранения, контекста, независимого писателя,
аварий и SDK находятся в парном PR DeepSeek Harness. Они дополняют этот UI
сценарий. Возврат пакета разрешён после возврата перенесённых чатов к исходным
каталогам; одной замены manifest для отката недостаточно.

## Подготовка прежнего профиля

Основной Desktop должен быть полностью закрыт штатным способом. Сохрани
manifest, lockfile, workspace и cordis-файлы профиля до обычной установки пакета.
Не копируй аккаунтные файлы и не редактируй node_modules вручную.

После штатной установки точного проверенного пакета выполни его
`scripts/prepare-relocation-profile.mjs` через установленный Node/Electron runtime.
Аргументы: `--profile <каталог профиля> --home <DSH_HOME> --install-anchor
<resources/app.asar/dsh/node_modules/@deepseek-ai/dsh/package.json> --confirm-closed`.
Для Electron используется процессная переменная `ELECTRON_RUN_AS_NODE=1` и
`--expose-internals`; это не меняет настройки Desktop или модели.

Подготовка не запускает плагины. Она сохраняет raw config, disabled и inject
единственного стандартного Schedule под прежним родителем, отключает старую
строку и добавляет совместимого владельца. Отсутствующий или выключенный
планировщик не включается. Полностью скомпонованная конфигурация привязана к
fingerprint; неоднозначный/сторонний/изолированный владелец отклоняется.
Произвольные include-файлы и динамические группы этой поставкой не принимаются.
Первоначальные пользовательские overrides сохраняются в
`cordis.relocation-cold.original.yml`; это конфигурационный backup, не auth backup.

Новая конфигурация требует повторной подготовки при полностью закрытом Desktop.
Не используй подготовку как горячую замену работающего владельца расписаний.
При отказе fingerprint закрыть Desktop и повторить подготовку; защита переноса
до этого не обходится. Новые аргументы запуска, меняющие подготовленное дерево,
также требуют отдельной подготовки.

Для отката сначала верни перенесённые чаты в исходные проекты, полностью закрой
Desktop и выполни ту же команду с `--remove` до удаления пакета. Затем восстанови
проверенные прежние пакеты/metadata и проверь чтение чата и расписаний прежним
владельцем. При stale fingerprint сначала повтори подготовку, сохранив текущие
файлы; команда удаления не выбрасывает непроверенные изменения.
